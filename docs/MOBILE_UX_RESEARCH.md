# მობილური 3D პორტფოლიო — კვლევა და გადაწყვეტილება

v0.14.5-ის წესი. მობილურზე 3D მოწყობილობა აჩვენებს აპის დესკტოპის საწყის ეკრანს. Try Now ხსნის HUD-ს და ვიზიტორს კომპიუტერზე ცდას სთავაზობს. იგივე წესი ვრცელდება მომავალ ინტეგრაციებზე. ქვემოთ აღწერილია v0.14.3-ის კვლევა და მაშინდელი გადაწყვეტილება.

შემოწმებულია: 2026-11-19. ეხება ამ პორტფოლიოს v0.14.3-ს. ქვემოთ წყაროების აღწერა და ჩვენი რეკომენდაციები განცალკევებულია. ეს არ არის უნივერსალური წესი, რომ ტელეფონს 3D არ უნდა ჰქონდეს.

## საჭიროა თუ არა 3D ტელეფონში?

**ჩემი რეკომენდაცია:** 3D სასარგებლოა როგორც დასამახსოვრებელი ვიზუალური პრეზენტაცია, მაგრამ პროექტის ნახვისა და აპის გამოცდის აუცილებელი წინაპირობა არ უნდა იყოს. დიზაინერის პორტფოლიოში ნამუშევრის სწრაფად გაგება უფრო მნიშვნელოვანია, ვიდრე მოწყობილობის ბრუნვა. პროექტის სურათი, აღწერა და მოქმედების ღილაკი ჩვეულებრივ კოლექციაშიც ხელმისაწვდომი უნდა დარჩეს.

ამ განახლებაში მობილური 3D გალერეა შენარჩუნებულია. MeeTab-ის Try now ტელეფონსა და touch მოწყობილობაზე ხსნის ცალკე სრულეკრანიან დემოს. დესკტოპზე აპი კვლავ პლანშეტის რეალურ ეკრანს მიჰყვება. ეს არის კონკრეტული არჩევანი ამ პროექტისთვის; ქვემოთ მოყვანილი წყაროები არ ავალდებულებს ყველას იმავე არქიტექტურას.

## კონკრეტულად რა იყო არასწორი

1. `ShapeGeometry`-ის ტექსტურის UV იყენებდა მოდელის XY კოორდინატებს. სურათს სჭირდებოდა ნორმალიზებული 0–1 UV. განსაკუთრებით ჩანდა MeeTab-ზე, სადაც DOM სურათის შემცვლელი ფენა დამალული იყო.
2. ტელეფონის Try now ქმნიდა ბრტყელ, სტატიკურ app plane-ს, ხოლო 3D პლანშეტი კვლავ ბრუნავდა. გამოსახულება მოწყობილობას შორდებოდა; წინა ტესტი მხოლოდ ხელით გადათვლილ წერტილზე tap-ს ამოწმებდა და ვიზუალურ/სამომხმარებლო პრობლემას ვერ იჭერდა.
3. ნეონი ეკრანის შიგნით იყო მოქცეული და მოკლე ანიმაციის ბოლოს ქრებოდა. მომხმარებლის განზრახვა იყო მთელი კორპუსის გარე განათება.

## პროფესიონალური desktop → phone ადაპტაცია

- ერთი კონტენტი და პროექტების იდენტობა; სხვადასხვა განლაგება და შეყვანის მართვა საჭიროების მიხედვით.
- დესკტოპზე დიდი 3D მოწყობილობა და შიგნით აპი შესაძლებელია. ტელეფონში დემოს გახსნა მკაფიო ცალკე რეჟიმია, დაბრუნების ღილაკით.
- მობილურზე აპის home/calendar/booking გვერდები გადალაგებულია სიგანის მიხედვით; ფორმას აქვს scroll, შეყვანა აღარ ატრიალებს 3D მოწყობილობას. landscape-ში გადაბრუნება აუცილებელი არ არის.
- cover გალერეაში ტექსტურაა; live iframe ნაჩვენებია მხოლოდ დემოს დროს. ეკრანისა და კორპუსის განათებას სხვადასხვა საზღვარი აქვს.
- ნეონი არის კორპუსზე მიბმული გარე SVG: მუდმივი halo და მოძრავი მცირე მონაკვეთი. Reduced motion ტოვებს უძრავ კონტურს.
- დაბრუნებისას იგივე iframe და სესიის მდგომარეობა რჩება. გვერდის reload-ზე შენარჩუნება დაპირებული არ არის.
- ტელეფონში მძიმე განათების ეფექტები გამარტივებულია, რეზოლუცია და კადრების სიხშირე შეზღუდულია; დაფარული დემოს ფონზე 3D არ იხატება.

## შემდგომი არჩევანი და საზღვრები

მომავალში **მობილურზე ნაგულისხმევი კოლექცია + სურვილისამებრ Open 3D** ყველაზე პრაქტიკული ვარიანტია სწრაფი პორტფოლიოსთვის. ამ პატჩში 3D ავტომატურად არ გამორთულა, რადგან მომხმარებელს მისი გამოყენება სურს. ასეთი შემდგომი არჩევანი სასურველია დაყრდნობილი იყოს რეალურ ტელეფონებზე ჩატვირთვის/სითბოს/ბატარეის შემოწმებასა და ვიზიტორების ქცევაზე, არა მხოლოდ browser emulation-ზე.

ეს არის პორტფოლიოს responsive ადაპტერი ძირითადი სამი გვერდისთვის, არა MeeTab-ის წარმოების mobile პროდუქტის სრული redesign. ანგარიშები და backend გათიშულია; ჯავშანი ლოკალური sample data-ია. ამ კვლევაში ნახსენები სხვა საიტების მიმდინარე 3D ქცევა ფიზიკურ ტელეფონებზე არ დატესტილა — შედარება ემყარება მათ გამოქვეყნებულ დოკუმენტაციასა და კონტროლებს.
