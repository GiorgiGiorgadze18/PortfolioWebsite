## პრობლემები და გადაწყვეტილება

სამ აქტიურ გვერდზე index.css, about.css და contact.css ზუსტად ერთნაირ ძირითად :root ტოკენებს შეიცავდა. ახლა ისინი css/tokens.css-დან იტვირთება, შესაბამის გვერდის CSS-მდე. გვერდების responsive override-ები მათ ადგილზეა. ოთხი ძირითადი გვერდის მთლიანი სტილების მექანიკური გაერთიანება არ შესრულებულა: Projects-ის მიმდინარე shell-ს showroom.css და საკუთარი ცვლადები ემსახურება. ძველი css/projects.css და css/style.css ამჟამინდელი ოთხი შესასვლელიდან არ იტვირთება. მათი შესაძლო გარე მომხმარებლების დასადგენად არსებული ფაილები დაცულია.

პროექტების დეტალები და სცენის განლაგებები showroom.js-ში იყო ჩაწერილი, ხოლო Home-ის სახელები და კატეგორიები ხელით ივსებოდა. ახლა data/projects.mjs ინახავს ექვსივე ჩანაწერს. სცენა იყენებს იმავე PROJECTS/ARCHIVE_PROJECTS მონაცემებს. ნახაზის, კამერის, მოწყობილობის და დემოს საზღვრების ველები უცვლელია. ძველი MeeTab ID jbl შენარჩუნებულია უკვე არსებული ბმულებისა და ტესტების თავსებადობისთვის. მომავალ ცალკე Case Study-ისთვის ჩანაწერის ID და #project/ ბმული უკვე არსებობს. ასეთი გვერდის შექმნა ამ ფაზაში არ განხორციელებულა.

Home-ის ბარათები რჩება საწყის HTML-ში. tools/sync-projects.mjs სინქრონიზებს მათ სათაურს, კატეგორიას, წელს, ნამუშევრის არჩევანსა და პირდაპირ ბმულს. featuredTitle და featuredArtwork განსაზღვრავს არსებული მოკლე სათაურის/სქრინის პრეზენტაციას იმავე საერთო წყაროში. კოდის ცვლილების შემდეგ გაუშვით node tools/sync-projects.mjs. node tools/sync-projects.mjs --check ამოწმებს სინქრონიზაციას ფაილის ჩაწერის გარეშე. browser runtime-ს Node არ სჭირდება. ## აქტივები და framework სტრატეგია

ორიგინალი artwork და ორივე აპის წყაროები ამ ფაზაში არ შეცვლილა. ფაზა 00-ში რვა ვიზიტზე ZIP მოთხოვნა ნული იყო, ამიტომ რეპოზიტორიის 22.66MB არქივის წაშლა ქსელის ოპტიმიზაციის მტკიცებულებით არ გამართლდა. რეალური გადაცემის მიზნობრივი ოპტიმიზაცია შემდეგ ფაზაში საჭიროა მოთხოვნილი სურათების და დემოს prewarm-ის გაზომვით. არც ფაილის სახელი და არც მასშტაბი საკმარისია წასაშლელად.

შეირჩა სტატიკური HTML, სტანდარტული ES module მონაცემები და პატარა შემოწმების სკრიპტი. Astro/TypeScript მიგრაციის სარგებელი უნდა შევადაროთ build-ის ფასს მაშინ, როცა მეტი დამოუკიდებელი გვერდი ან საერთო შაბლონი გაჩნდება. ამ ეტაპზე ორიგინალური WebGL-ის და iframe ინტეგრაციის მიგრაციის რისკი უფრო დიდ სამუშაოს მოითხოვს. ავტორიზაციის მოთხოვნა მნიშვნელოვანი framework მიგრაციისთვის ძალაში რჩება.
